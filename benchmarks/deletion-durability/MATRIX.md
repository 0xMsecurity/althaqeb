**Vector Database Deletion-Durability Registry v0.1.0**

For each storage engine: after an official delete() returns success and the logical layer reports clean, does the embedding vector persist bit-identically on disk, what (if anything) reclaims it, and how long is the recovery window? Every quantitative claim traces to a committed result file under experiments/residue/results/. Build with build_matrix.py (fails if any cited evidence is missing).

## Method

Exact float32 byte-substring search (raw + L2-normalized) of the on-disk store, with a live-filler positive control to prove the search would find a present vector. cosine>0.999 / bit-identical = present. Recovery window = interval between delete() and the first reclamation pass that purges the residue.

## Window-class taxonomy

- **unbounded** — no reclamation observed under any tested pressure (writes, restarts, drop, idle)
- **auto-timed** — an automatic background pass purges it; a purge time was measured
- **auto-untimed** — an automatic pass (optimizer/autovacuum) purges it, but no purge time was measured here
- **manual-only** — only an explicit operator command purges it
- **none** — no residue — engine reclaims at write/close (true negative)
